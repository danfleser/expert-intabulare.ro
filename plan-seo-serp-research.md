# SERP Research & Transactional-Query Optimization — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise rankings for transactional cadastru/intabulare queries in Alba county by reverse-engineering the live SERP, then applying proven patterns to 6 flagship pages through the generator's data layer.

**Architecture:** Three phases with a hard gate between research and mutation. Phase A captures live Google SERPs through the CEO's logged-in Chrome and extracts competitor pages into a fixed JSON schema. Phase B distills those into confidence-ranked findings and picks 6 flagships. Phase C edits *only* `generator/data/**` and rebuilds — never `docs/` HTML — with an automated check that the render-gate demotion count never rises above the 92 baseline.

**Tech Stack:** Node.js (zero-dep generator already in repo), `mcp__claude-in-chrome__*` browser tools, plain JSON artifacts, git.

## Global Constraints

- **Never hand-edit anything under `docs/`.** It is the GitHub Pages webroot and is fully regenerated by `node generator/build.js`. All content changes go into `generator/data/**`.
- **Never place internal docs under `docs/`.** Research artifacts live in `research/seo-2026-07/`, specs and plans at repo root.
- **Contact is WhatsApp-only** (standing CEO order). Never introduce an email form, mailto link, or contact form. WhatsApp URL form: `api.whatsapp.com/send/?phone=40741478540&text=<prefill>`.
- **Verification gate for every data change:** `node generator/build.js && node generator/verify.js` must exit 0, AND render-gate demotions must be `<= 92`.
- **Baseline demotion count: 92** (from `generator/build-report.txt`, buildDate 2026-07-29).
- **Romanian content must keep correct diacritics** (ă, â, î, ș, ț) in page copy, matching existing `localNote` style. Query strings captured from Google may be diacritic-free; that is expected and is data, not copy.
- **Render-gate limits** (`generator/lib/gates.js`): `MIN_UNIQUE_WORDS = 120`, `MAX_SHINGLE_OVERLAP = 0.7`, `MAX_LEAF_BYTES = 61440`.
- **The 12 service slugs** are: `cadastru-si-intabulare`, `intabulare-teren`, `intabulare-casa-constructie`, `intabulare-apartament`, `dezmembrare-alipire`, `plan-topografic`, `trasare-teren`, `actualizare-carte-funciara`, `topografie-constructii`, `servicii-ocpi`, `certificat-energetic`, `expertize-documentatii`.
- Commit after every task. Never commit with a failing verify.

```js
'use strict';
// Guards Phase C: the render-gate demotion count must never rise above baseline.
// A content change that demotes more pages than it rescues is a regression.
const fs = require('fs');
const path = require('path');

const DEFAULT_BASELINE = 92;

/** @param {string} report contents of build-report.txt @returns {number} */
function parseDemotions(report) {
  const m = report.match(/^Render-gate demotions:\s*(\d+)\s*$/m);
  if (!m) throw new Error('Render-gate demotions line not found in build report');
  return Number(m[1]);
}

function main() {
  const max = Number(process.argv[2] ?? DEFAULT_BASELINE);
  const reportPath = path.join(__dirname, '..', '..', 'generator', 'build-report.txt');
  const n = parseDemotions(fs.readFileSync(reportPath, 'utf8'));
  console.log(`demotions=${n} baseline=${max}`);
  if (n > max) {
    console.error(`FAIL: demotions rose from ${max} to ${n}`);
    process.exit(1);
  }
}

if (require.main === module) main();
module.exports = { parseDemotions, DEFAULT_BASELINE };
```

`priceDisclosure` is one of exactly `"none"`, `"range"`, `"exact"`. `durationClaim` is the stated turnaround string, or `null`.

- [ ] **Step 1: Build the dedupe list**

Take the top 5 organic results from each SERP capture, union them, drop duplicates by URL, and drop any expert-intabulare.ro URL (that is us, not a competitor). Expect roughly 40–50 unique pages. Record which queries each URL ranked for in `rankedFor`.

- [ ] **Step 2: Extract each page**

Navigate to each URL and fill the schema. Notes on the tricky fields:

- `wordCount` — the main content region only. Exclude header, footer, nav, cookie banners.
- `subtopics` — the substantive things the page actually covers (e.g. "documente necesare", "durata", "costuri OCPI"), not its headings verbatim.
- `schemaTypes` — read the `<script type="application/ld+json">` blocks and list the `@type` values.
- `trustSignals.ancpiAuthNumber` — true if an ANCPI/OCPI authorization number is shown anywhere on the page.

If a page fails to load after two attempts, record it with `"error": "unreachable"` and move on. Do not stall the whole task on one dead competitor.

## Task 5: Confidence-ranked gap analysis and flagship selection

**Files:**
- Create: `research/seo-2026-07/findings.md`
- Create: `research/seo-2026-07/flagships.json`

**Interfaces:**
- Consumes: `queries.json`, `serp/*.json`, `competitors/*.json`.
- Produces: `flagships.json` — array of `{ service, locality, url, queryId, gaps: [gapId], plannedEdit: { file, field, rationale } }`, consumed by Tasks 6 and 7.

- [ ] **Step 1: Compute competitor consensus per field**

For each extracted field, compute how many of the top-5-ranking pages exhibit it. Example: `priceDisclosure != "none"` in 8 of 10 pages.

- [ ] **Step 2: Diff against our equivalent page**

For each query, our page is `docs/servicii/<service>/<county>/<locality>/index.html`. Read it and score it on the same schema as competitors, so the comparison is like-for-like.

- [ ] **Step 3: Write `findings.md` with confidence tags**

Every gap gets exactly one confidence tag, and the rule for assigning it:

- **High** — near-unanimous among top rankers AND mechanically checkable. Example: "8/10 top results state a price range; we state orientative ranges only."
- **Low** — correlational only. Example: "top result has 2,400 words vs our 900." Length correlates with rank without causing it.

Each finding must state whether it is expected to **move rankings** or is **table stakes** (needed to look credible but unlikely to change position).

Include a mandatory section titled `## What this analysis cannot tell you` stating: SERP analysis shows correlation, not causation; the domain went live 2026-07-28, so a large share of the gap is domain authority and age that no on-page edit addresses; and map-pack results are governed by Google Business Profile, not page content.

Do not write a "do these N things and you will rank #1" conclusion. That claim is not supported by this method.

- [ ] **Step 4: Select exactly 6 flagships**

Rank candidate pages by `(commercial value of the query) × (size of closable on-page gap)`. Pick the top 6. Write `flagships.json`. Every `plannedEdit.file` MUST be under `generator/data/` — if a planned edit names a path under `docs/`, it is invalid by the Global Constraints and must be rewritten.

## Task 8: Recover near-miss demoted pages

Independent of the research, and pure upside: dozens of the 92 demoted pages miss the 120-word floor by a single word. Each recovery is a page that goes from non-existent to indexable.

**Files:**
- Modify: `generator/data/localities/*.json`

**Interfaces:**
- Consumes: `generator/build-report.txt`.
- Produces: a lower demotion count; new baseline recorded.

- [ ] **Step 1: List the near-misses**

```bash
cd "website pfa deploy" && node -e "
const fs=require('fs');
const rep=fs.readFileSync('generator/build-report.txt','utf8');
const rows=[...rep.matchAll(/^  - (\S+): unique words (\d+) < 120$/gm)]
  .map(m=>({page:m[1],words:Number(m[2])}))
  .filter(r=>r.words>=110)
```
